## Kept on purpose

- Panel text at 11.5px and 12.5px: DevTools density, the same scale Chrome DevTools uses. The
  impeccable detector flags it as `tiny-text`; DESIGN.md owns that choice.
- 44px tap targets (R-03) do not apply: the panel and popup only exist in desktop Chrome.
- `→` in "Open DevTools → WasmCheat" is a menu path, not a button decoration (R-08).
- Fieldset legends sitting on the card border, and `Value:` style labels with colons: the Cheat
  Engine group box the panel deliberately echoes.
- The demo's molten palette and radial glow on the score card: the score is the one thing a visitor
  scans for, so it is the focal point (DESIGN.md, "The demo is the exception").
- The modal palette, the help sheet and the demo board keep a wide soft shadow (impeccable flags
  `thin-border-wide-shadow`): each is the one surface lifted above everything else (R-12).

## Follow-up: the job, made shorter (same day)

The panel exists for one job: see a number in a game, find where it lives, change it. Before, the
last step happened two cards away from the hit you clicked, and the panel asked for Attach even when
the agent was already in the page.

| # | Change | Why |
| --- | --- | --- |
| 20 | Clicking a hit opens an editor under the Found list: current value, **Write** (or Enter), **Freeze** / **Unfreeze**. | Step 3 now happens where step 2 ends (C-3). |
| 21 | When the agent is already in the page, the panel lists the wasm on its own, fills the instance, and starts on step 2. **Attach** is highlighted only when there is nothing to scan yet. | One step fewer on every normal page. |
| 22 | Memory view, Read and write and Instances moved into **More tools**. The palette opens the tray when it jumps to one of its cards (it used to scroll to a hidden card). | The first screen holds the loop and nothing else. |
| 23 | The bridge token box is hidden unless the bridge needs a token, the same rule as the popup. The version line moved to the status bar. | A repair tool is not a step. |
| 24 | Hints rewritten as instructions ("Type a number you can see in the game and press First Scan…"); "Reads / writes" became "Read and write"; the demo tip, popup hint, `npm run demo` output and README quick path no longer tell people to approve or attach first. | R-15, R-16: say the action. |

## Delivery Gate (after both passes)

Hard Gate: no em dash in any UI string or doc (grep: 0 outside code comments). No statistics, testimonials or invented
claims; the manifest no longer promises an approval step. Every control does something: the new
Write and Freeze buttons are exercised by `tests/e2e/screenshots.spec.ts`. Empty, waiting and error
states exist for Found, the editor (`pick-out` shows refusals in the danger tint), the popup and the
token box. Keyboard: every control is a native button, input or select; Enter writes from the editor;
palette and help close on Escape; the focus ring is unchanged. Both panel themes were captured
(`docs/img/panel.png`, `panel-dark.png`). Contrast measured for every token pair (lowest 4.84:1, `--ink-3` on a dark input).
Direction: `docs/DESIGN.md`, dial ENERGY 1 / RHYTHM 1 / MOTION 1. Verified: `npm run build`,
`npm run typecheck`, 158 unit and 26 end-to-end tests.

Purpose-Gate: one accent, used on the primary action, live pills, interactive addresses and now
the editor (the place the answer is). Two blurred bars (topbar, status bar), within the dose cap. No
arrows on buttons, no capsule badges left on the demo, no decorative icons.

Liveliness: focal point per screen is the next action (First Scan, then Next Scan, then Write). The
identity motif is the Now crumb (tab · instance · address) plus monospace for machine text only.
